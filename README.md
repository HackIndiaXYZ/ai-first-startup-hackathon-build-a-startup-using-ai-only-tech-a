# Dukaan Dost

**A voice- and text-based order desk that helps small shopkeepers turn customer requests into reviewed orders and keep track of payments still due.**

Dukaan Dost is a hackathon project for the everyday bookkeeping gap between taking an informal order and remembering what was delivered, paid, or left outstanding.

## Features

- **Voice or text order capture.** Type an order or record/upload a voice note for transcription. The transcript is editable before extraction. The interface supports Hindi, Hinglish, English, Marathi, Bengali, Tamil, and Auto-detect for capture/transcription.
- **Review before confirming.** Extraction creates a draft for the signed-in owner. Review and edit its transcript and extracted details; an order is created only after confirmation.
- **Order and payment history.** View order totals, dated payment entries, paid totals, balances, and printable receipts. Payments are manual records of money already received.
- **Outstanding dues.** Search by customer name, sort by highest balance or oldest order, and record a payment from an individual due. Amounts must be positive and cannot exceed the current balance.
- **Due-date status and overdue highlighting.** Due cards show “Due date not set,” “Due today,” “Due in N days,” or “N days overdue,” calculated using the Asia/Kolkata business date. Orders older than seven days are highlighted.
- **Reminder log.** Creating a reminder draft and opening its WhatsApp or SMS action records the customer, language, time, and action. The latest log date is shown with the due.
- **Template-based reminders.** Local Java templates create editable Hindi, Hinglish, English, Marathi, Bengali, and Tamil drafts with the remaining balance. The owner can copy the message or open WhatsApp/SMS with it prefilled.
- **UPI reminder link.** If `UPI_ID` is configured, the message includes a `upi://pay` link with the outstanding INR amount. This only creates a link; the owner still chooses whether to share it.
- **Payment-by-voice/text review.** Report a payment in the capture area, review the extracted customer, matching outstanding order, amount, and note, then explicitly confirm before it is recorded.
- **Customer ledger.** Open a customer from a due or order history entry to see their dated orders and payments, running balance, current outstanding, and a print / Save as PDF view.
- **Today summary.** See confirmed orders and payments for the Asia/Kolkata business date, plus current outstanding dues.
- **Owner accounts.** Email/password sign-up with email verification, session login, password reset, optional Google sign-in, profile and preferences. Customer, draft, order, and payment access is scoped to the signed-in owner.

## Tech stack

- Java 21 and Spring Boot 3.5.6
- Spring MVC, Spring Security, Jakarta Validation, Spring Data JPA
- PostgreSQL and Flyway
- Spring AI OpenAI-compatible client configured for Gemini text extraction
- Gemini REST API for voice-note transcription
- Static HTML, CSS, and JavaScript frontend served by Spring Boot

## Architecture overview

The browser UI sends authenticated, CSRF-protected requests to Spring REST controllers. Draft workflow services save owner-scoped drafts, call the extraction service, and pass extracted values through validation. Confirming a reviewed draft creates the order; payments are stored separately and the outstanding balance is calculated from recorded payments.

Audio uploads are sent to the transcription endpoint and returned as editable text; the app does not attach the recording to an order. Reminder messages are generated by local templates rather than a model or messaging provider. Reminder actions are persisted in the reminder log.

## Setup

### Prerequisites

- Java 21
- Maven
- PostgreSQL
- A Gemini API key for text extraction and voice transcription

Create a PostgreSQL database named `dukaan_dost` (or configure another database URL), then set the environment variables to match your local PostgreSQL account:

```bash
export DB_URL="jdbc:postgresql://localhost:5432/dukaan_dost"
export DB_USERNAME="postgres"
export DB_PASSWORD="<YOUR_POSTGRES_PASSWORD>"
```

Set the Gemini key in your shell. Replace the placeholder locally; do not commit the value:

```bash
export GEMINI_API_KEY="<YOUR_GEMINI_API_KEY>"
```

Gemini is the default extraction mode. The app also accepts `EXTRACTION_MODE=fake` for its deterministic extraction path; this does not provide fake voice transcription.

For email verification and password reset, configure SMTP. Without SMTP, email/password sign-up cannot complete verification; Google sign-in can be configured separately. Optional Google OAuth uses the registered redirect URL `http://localhost:8080/login/oauth2/code/google`.

Optional shop label and UPI details for reminder drafts:

```bash
export SHOP_NAME="<YOUR_SHOP_NAME>"
export UPI_ID="<YOUR_UPI_ID>"
```

### Build and run

Build the application without invoking model integration tests:

```bash
mvn -DskipTests package
```

Start the Spring Boot app:

```bash
mvn spring-boot:run
```

Flyway applies database migrations at startup. Open [http://localhost:8080/](http://localhost:8080/) and create an owner account to use the app.

Configure `SPRING_MAIL_HOST`, `SPRING_MAIL_PORT`, `SPRING_MAIL_USERNAME`, `SPRING_MAIL_PASSWORD`, `MAIL_FROM`, and `APP_BASE_URL` for email verification and password-reset messages. Google OAuth requires `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`. The optional SMS environment placeholders do not currently enable an SMS OTP provider.

## Tests

Run the automated suite:

```bash
mvn test
```

Unit tests use mocks for model-dependent behavior. The live extraction integration tests are skipped when `GEMINI_API_KEY` is unset; when it is set, those tests make requests to Gemini. The mocked language tests verify the app's handling and mapping, not the model's real-world transcription or extraction quality.

## Safety and data handling

- Extraction saves a draft for review; an order is created only after the owner checks the details and confirms it.
- Voice recordings are sent for transcription only and are not retained as order attachments. The returned transcript remains editable.
- Nothing is sent automatically. WhatsApp and SMS actions only open a prefilled draft; the owner decides whether to send it.
- Payment recording does not transfer or collect money. There is no wallet or payment gateway.
- Authentication, owner-scoped data access, session security, and CSRF protection are enabled.
- A UPI link is included only when the owner configures `UPI_ID`; no payment is collected or initiated by the app.
- Do not put API keys or passwords in source control. Configure them through environment variables.

## Limitations and future ideas

This is a hackathon MVP, not a production accounting or payment system. AI output can be wrong and must be reviewed. Gemini access requires network connectivity and a configured key; the automated mocked tests do not establish live model quality. The app currently offers only the six listed Indian languages and does not claim support for other languages. SMS OTP and browser push delivery are not implemented; their preferences/placeholders do not mean a provider is active. Rate limits are held in memory per app instance.

Possible future work (not implemented): evaluate extraction and transcription with consented real-world samples, add export/backup workflows, improve mobile usability, and consider durable shared rate limiting for multi-instance deployments.
